
# 📝 产品需求文档 (PRD)：Obsidian Image Toolkit Extended

## 1. 产品背景 (Background)
**Obsidian Image Toolkit** 提供了极佳的图片交互体验（缩放、旋转、反色、贴图），但其局限在于仅支持标准的 `<img>` 标签。随着“文档即代码”趋势，用户在 Obsidian 中大量使用 **Mermaid, D2, PlantUML** 等工具。目前这些图表在放大查看、细节比对方面体验较差，缺乏统一的视觉操作套件。

## 2. 核心目标 (Objective)
通过扩展原有的拦截逻辑，实现对 **“文本生图 (Text-to-Diagram)”** 容器的识别与接管，让动态生成的 SVG 图表也能像普通图片一样：**点击弹出、自由缩放、置顶贴图**。

## 3. 用户痛点 (Pain Points)
* **查看难**：复杂的架构图（如 Mermaid 流程图）在笔记中显示过小，难以看清细节。
* **交互断层**：普通图片可以放大操作，但紧邻的 D2 图表却只能固定在页面上。
* **场景受限**：写长文档时，无法将参考架构图（文本生）“贴”在屏幕上进行对照。

## 4. 功能范围 (Scope)

### 4.1 智能容器识别 (Smart Capture)
* **拦截范围扩展**：除了监听 `<img>`，新增对特定 CSS 类名的点击监听。
    * **优先级 1 (P0)**: `.mermaid` (最通用)
    * **优先级 2 (P1)**: `.block-language-d2`，兼容保留 `.d2-chart`
    * **兼容说明**: PlantUML 如果已经渲染为普通 `<img>`，继续走现有图片预览逻辑；仅当遇到 SVG-only 的 PlantUML 渲染器时，再追加 `.block-language-plantuml` 等选择器。
    * **优先级 3 (P2)**: 用户自定义 CSS 选择器 (可在设置页面配置)
* **动作响应**：点击上述容器时，自动提取其内部生成的 **SVG 元素**。

### 4.2 增强型预览器 (Extended Viewer)
* **矢量渲染支持**：预览层需兼容加载 SVG DOM，而非仅加载 `src` 链接。
* **功能复用**：
    * **缩放/移动**：保持原有的平滑缩放逻辑（针对 SVG 路径需确保不失真）。
    * **全屏查看**：支持复杂图表的一键全屏。
    * **反色/滤镜**：针对暗色模式用户，支持对 SVG 整体应用反色滤镜。
* **贴图模式 (Pin Mode)**：支持将文本图表直接固定在屏幕前端。

## 5. 用户流程 (User Flow)
1.  用户在笔记中撰写 Mermaid 或 D2 代码。
2.  Obsidian 渲染出可视化图表。
3.  用户**点击**图表（或配合修改键如 `Ctrl+点击`）。
4.  **插件介入**：拦截点击，捕获当前容器的 SVG。
5.  **弹出视图**：在遮罩层中显示放大后的图表，用户可进行缩放、平移。
6.  用户按 `Esc` 或点击遮罩退出。

## 6. 非功能需求 (Non-functional)
* **极致简洁**：遵循 **Refined Minimalism** 风格，不增加冗余的 UI。
* **低摩擦开发**：尽量复用原项目的 `ImageContainer` 逻辑，减少对核心架构的侵入性改动。
* **性能**：处理超大型 SVG（如 500+ 节点的流程图）时，缩放需保持帧率。

## 7. 推荐实现方案 (Implementation Plan)

### 7.1 总体策略
采用 **“图表转临时图片 URL，复用现有图片查看器”** 的方案，而不是为 Mermaid/D2/PlantUML 重新实现一套弹窗、缩放、拖拽和工具栏。

原因：
* 当前插件的核心交互已经围绕 `HTMLImageElement` 实现，包括点击打开、缩放、拖拽、全屏、反色、Pin 模式和快捷键。
* Mermaid/D2/PlantUML 最终通常会渲染为 SVG 或图片节点。只要把这些节点转换成可被 `<img>` 加载的 `src`，即可进入现有处理链路。
* 这样用户体感上和原插件保持一致，只是可查看对象从普通图片扩展到文本生成图。

### 7.2 第一阶段范围
第一阶段优先支持当前普通图片链路尚未覆盖的常见 Obsidian 渲染结果：
* `.mermaid`
* `.block-language-d2`
* `.d2-chart`（兼容保留）

PlantUML 在当前环境中如果已经渲染为普通图片，则保持原有处理方式，不默认拦截 `.block-language-plantuml`，避免改变现有图片交互和 Gallery Navbar 行为。

官方 D2 Obsidian 插件的渲染容器类名是 `.block-language-d2`，并且容器中可能带有 `.Preview__Recompile` 按钮。图表预览只接管图表点击，需避开该按钮，保证 D2 自带的重新编译功能仍然可用。

处理规则：
1. 点击上述容器时，先检查是否满足现有 `viewTriggerHotkey` 设置。
2. 从容器中提取可显示核心元素：
   * 优先使用容器内部的 `svg`
   * 其次使用容器内部的 `img`
   * 如果容器本身就是 `svg` 或 `img`，直接使用容器自身
3. 对 `svg` 使用 `XMLSerializer` 序列化为 SVG 字符串，再创建 `Blob` 和 `URL.createObjectURL()`。
4. 创建一个临时 `HTMLImageElement`，设置 `src`、`alt` 和必要的临时元数据，然后调用现有 `ContainerView.renderContainer()`。
5. 弹窗关闭、Pin 图被覆盖或刷新时，释放旧的 Blob URL，避免内存泄漏。

### 7.3 与现有交互的关系
该方案的目标是保持原有交互不变：
* 普通图片仍然按原逻辑处理。
* Mermaid/D2 图表打开后使用同一套查看器；PlantUML 如果渲染为普通图片，则继续走原图片查看器。
* 缩放、拖拽、反色、全屏、Pin 模式、快捷键尽量复用现有实现。
* 第一阶段不把图表加入 Gallery Navbar 切换列表，避免影响原有图库逻辑。

### 7.4 风险与后续增强
* 某些 SVG 只有 `viewBox` 没有 `width/height`，序列化前需要补齐尺寸。
* SVG 中依赖 Obsidian 主题 CSS 变量、外部字体或外部资源时，独立图片渲染可能和原页面略有差异。
* 复制图片功能在复杂 SVG 上可能受 Canvas 安全限制影响。
* 后续可增加用户自定义 CSS 选择器设置，用于兼容更多图表插件和自定义渲染器。
